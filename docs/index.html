🛡️

100% Freestanding Zero-CRT

Compiles strictly under -ffreestanding -nostdlib. Operates directly on Linux/Win32 kernel syscall boundaries with zero libc/libstdc++ dependencies.

📦

Zero-Linker ELF & PE Emitter

Includes a built-in AOT relocatable ELF (ElfEmitter) and PE32+ generator that builds .text and .rodata sections and patches relative relocations natively.

🚀

SSA AVX-512 Vectorization

Transforms scalar assembly loops into 256-bit AVX2 and 512-bit AVX-512 packed vector instructions, emitting non-temporal stores (vmovntdq + sfence) to bypass L1/L3 cache pollution.

🌐

Zero-Copy Hardware io_uring

Direct io-submit and io-poll opcode instructions lowering to kernel Submission Queue (SQ) and Completion Queue (CQ) ring buffers.

🔄

On-Stack Replacement (OSR)

Safe-point OSR tiering captures live CPU registers (RAX–R15) to transition running Tier-1 JIT loops mid-flight into Tier-3 hyper-unrolled vector loops.

    if-ge v0, p1, spigot_end

Frequently Asked Questions

Everything you need to know about Anastasia Engine, architecture, and deployment.

Anastasia Engine v7.1 is a high-throughput, bare-metal JIT & AOT compiler engine for a RISC-style intermediate assembly language called Anastasia Assembly (.ana). It compiles .ana code directly into native x86_64 (AVX2 / AVX-512) and ARM64 machine code with zero dynamic C-runtime dependencies.
The engine is compiled under -ffreestanding -nostdlib -fno-exceptions -fno-rtti. It completely bypasses standard C libraries (libc / libstdc++) and executes raw Linux/Win32 kernel syscalls directly via inline assembly (raw_mmap, raw_write, raw_clone, raw_futex).
Yes, absolutely! Language creators can write their frontend in any language (Python, Rust, C++, Go) and emit .ana as their Intermediate Representation (IR). Anastasia handles register allocation, SSA autovectorization, and standalone ELF/PE object file generation automatically without needing LLVM or external linkers.
Unlike LLVM which is heavy (>100MB binary footprint) and complex to embed, Anastasia is a lightweight (~1.5 MB) standalone binary. Unlike traditional assembly which is locked to a single CPU architecture, Anastasia Assembly (.ana) is portable and autovectorizes scalar code into 512-bit AVX-512 instructions.

It uses a freestanding frame-pointer stack unwinder (ExceptionUnwinder) that traverses stack frames without relying on GCC's libgcc_s.so. Low-level traps (like TLAB overruns) are handled gracefully via signal guard pages.

Anastasia natively supports x86_64 (with VEX 256-bit AVX2 & EVEX 512-bit AVX-512 encodings) and AArch64 (ARM64). It dynamically detects CPU features at runtime and routes instructions to optimal vector paths.
Anastasia uses a fast-path **Branchless Thread-Local Allocation Buffer (TLAB)**. Short-lived temporary objects are scalar-replaced directly into virtual registers via Escape Analysis (**0 heap allocations**). Long-lived objects use a trap-free VM write barrier Remset garbage collector.
